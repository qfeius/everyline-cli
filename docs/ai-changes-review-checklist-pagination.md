# AI 变更记录：审查清单对话分页

## 需求目标

- Codex、WorkBuddy 等宿主单次选择组件容纳不下全部审查清单时，用户仍可浏览并选择完整候选集合。
- 每页展示 4 个真实清单，使用稳定全局编号，并支持上一页、下一页和按名称搜索。
- 用户一次回复一个或多个有效编号；直接输入未展示清单的完整名称时在全部候选中匹配。
- 先单独完成清单选择，再通过下一次独立交互选择立场方，不把两类问题合并到同一选择卡片。

## 实现内容

- CLI 继续使用 `checklist list --page-size 100` 读取全部远端分页，接口和命令保持不变。
- Skill 冻结首次完整查询得到的候选顺序：内置规则包固定编号 `0`，真实清单从 `1` 连续编号。
- 真实清单按每页 4 项展示，页面固定显示 `第 X/Y 页`；翻页和搜索期间不重新编号。
- 名称搜索覆盖全部候选，重名时继续展示区分信息；一次回复中的多项选择统一映射为真实清单 ID。
- 收到至少一个有效规则来源后立即冻结清单状态，并在下一次独立交互进入立场方选择，不增加完成或确认步骤。
- Codex 当前回合提供原生结构化选项工具时，与 WorkBuddy 一样优先把立场方和强度显示为互斥单选选项卡；清单多选、分页和搜索保留稳定编号文字协议。

## 兼容性

- 不修改 CLI JSON、后端接口、分页参数、主体提取或任务发起结构。
- 清单不超过 4 项时只有一页，但清单和立场方仍使用两个独立阶段。
- Codex 当前模式没有原生选项工具时自动回退为相同编号交互，不为展示选项卡切换协作模式。
