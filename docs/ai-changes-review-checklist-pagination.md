# AI 变更记录：审查清单对话分页

> 后续调整：三端现已统一按「主体 → 强度 → 清单」执行。清单阶段读取全部远端分页，将内置项和真实清单组成统一候选，在正文完整展示所有候选（例如编号 0、1、2、3、4、5、6），等待用户回复一个或多个编号，不做对话分页或搜索导航，也不使用选项组件。以下历史记录中的分页、搜索和组件约定均已被替换，当前执行规则以 `skills/everyline-review/SKILL.md` 为准。

## 需求目标

- Codex、WorkBuddy 等宿主单次选择组件容纳不下全部审查清单时，用户仍可浏览并选择完整统一候选集合。
- 内置规则包与真实清单组成统一候选，每页最多展示 4 项，使用稳定全局编号，并支持上一页、下一页和按名称搜索。
- 用户一次回复一个或多个有效编号；直接输入未展示清单的完整名称时在全部候选中匹配。
- 先单独完成清单选择，再通过下一次独立交互选择立场方，不把两类问题合并到同一选择卡片。

## 实现内容

- CLI 继续使用 `checklist list --page-size 100` 读取全部远端分页，接口和命令保持不变。
- Skill 冻结首次完整查询得到的候选顺序：内置规则包固定编号 `0`，真实清单从 `1` 连续编号，二者组成统一候选快照。
- 统一候选按 `pageSize=4` 逻辑分页，页面固定显示 `第 X/Y 页`；翻页和搜索期间不重新编号。6 个真实清单加内置项共 7 项时，第 1 页为 0、1、2、3，第 2 页为 4、5、6。
- 名称搜索覆盖全部候选，重名时继续展示区分信息；一次回复中的多项选择统一映射为真实清单 ID。
- 收到至少一个有效规则来源后立即冻结清单状态，并在下一次独立交互进入立场方选择，不增加完成或确认步骤。
- WorkBuddy 的清单阶段固定调用 `AskUserQuestion` 并设置 `multiSelect=true`，当前页统一候选写入组件 `options`；主体和强度使用同一组件的单选模式。
- Codex 当前回合提供原生结构化选项工具时，立场方和强度显示为互斥单选选项卡；当前只支持互斥单选的 Codex 和未暴露选项能力的豆包在清单阶段使用相同分页快照的稳定编号协议。

## 兼容性

- 不修改 CLI JSON、后端接口、分页参数、主体提取或任务发起结构。
- 统一候选不超过 4 项时只有一页，但清单和立场方仍使用两个独立阶段。
- WorkBuddy 未暴露或拒绝 `AskUserQuestion` 时保留分页快照并报告组件能力缺口，不用 Markdown 表格替代组件。
- Codex 当前模式没有原生选项工具时自动回退为相同编号交互，不为展示选项卡切换协作模式。
