# 影响评审：审查清单对话分页

## 能力变化

本变更只调整 EveryLine Skill 的对话编排，不修改 CLI 或远端接口。内置规则包与真实清单组成统一候选快照；6 个真实清单加内置项时，第 1 页为 0、1、2、3，第 2 页为 4、5、6。WorkBuddy 清单固定使用 `AskUserQuestion` 且 `multiSelect=true`，Codex 和豆包复用同一快照的编号协议。

## 潜在回归

- 统一候选不超过 4 项时仍拆分交互，会比原来多一次卡片，但消除了两个业务问题混排的歧义。
- 翻页后若编号或候选顺序变化，可能把显示名称映射到错误 ID。
- 名称重复时若直接按名称选中，可能产生歧义；必须继续展示区分信息。
- 用户分多轮发送清单编号会因首次有效回复立即进入下一阶段；交互提示必须明确多选需在同一次回复中给出。
- WorkBuddy `AskUserQuestion` 每个问题最多承载 4 个选项，因此清单页面容量固定为 4；组件缺失时流程会暂停并保留快照，不再输出 Markdown 表格。

## 测试覆盖

- 场景矩阵覆盖单页、多页、前后翻页、跨页浏览后按稳定编号选择、全局名称搜索、重名、两阶段隔离、WorkBuddy 原生多选，以及 Codex/豆包编号回退。
- Skill 快速校验检查入口与引用结构。
- diff 检查确保文档格式正常。

## 发布与回滚

随下一版 CLI 包发布并重新安装 Skill 后，Codex、WorkBuddy 和豆包使用对应宿主流程。回滚仅恢复 Skill 与配套文档。
