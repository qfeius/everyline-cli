# 影响评审：审查清单对话分页

## 能力变化

本变更只调整 EveryLine Skill 的对话编排，不修改 CLI 或远端接口。用户可在 Codex、WorkBuddy 等宿主中分批浏览全部清单，并在清单完成后单独选择立场方；Codex 当前回合提供原生选项工具时，立场方和强度可直接使用单选选项卡。

## 潜在回归

- 清单不超过 4 项时仍拆分交互，会比原来多一次卡片，但消除了两个业务问题混排的歧义。
- 翻页后若编号或候选顺序变化，可能把显示名称映射到错误 ID。
- 名称重复时若直接按名称选中，可能产生歧义；必须继续展示区分信息。
- 用户分多轮发送清单编号会因首次有效回复立即进入下一阶段；交互提示必须明确多选需在同一次回复中给出。
- 把 Codex 的互斥单选工具用于清单会丢失多选语义，因此清单仍需稳定编号文字协议，直到宿主组件明确支持完整多选与导航。

## 测试覆盖

- 场景矩阵覆盖单页、多页、前后翻页、跨页浏览后按稳定编号选择、全局名称搜索、重名、两阶段隔离，以及 Codex/WorkBuddy 单选选项卡与编号回退。
- Skill 快速校验检查入口与引用结构。
- diff 检查确保文档格式正常。

## 发布与回滚

随下一版 CLI 包发布并重新安装 Skill 后，Codex、WorkBuddy 和豆包使用对应宿主流程。回滚仅恢复 Skill 与配套文档。
