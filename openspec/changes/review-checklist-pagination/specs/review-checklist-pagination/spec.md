# 审查清单完整展示规格

本规格替代原对话分页方案。Codex、豆包和 WorkBuddy 统一按「主体 → 强度 → 清单」执行，主体与强度的既有单选方式保持不变。

## Requirement: 完整读取并展示全部规则来源候选

EveryLine Skill MUST 读取 CLI 返回的全部远端分页，把内置项和真实清单组成统一候选，在回复正文完整展示所有候选，不做对话分页，不提供翻页或搜索导航，不使用清单选项组件。

### Scenario: 清单超过四项

- **GIVEN** 主体和强度已确定，内置项与真实清单合计超过 4 项
- **WHEN** Skill 进入清单选择阶段
- **THEN** 必须完整展示所有候选，内置项固定编号 0，真实清单从 1 连续编号
- **AND** 6 个真实清单加内置项时，完整展示编号 0、1、2、3、4、5、6
- **AND** 清单较长时允许连续分段输出，但必须全部展示后再等待用户回复

### Scenario: 服务端返回多页清单

- **GIVEN** CLI 返回的清单有多个远端分页
- **WHEN** Skill 读取清单
- **THEN** 必须继续取完所有页并冻结完整候选与编号映射
- **AND** 不得仅展示第一批数据或要求用户翻页以继续读取

## Requirement: 用户通过编号选择一个或多个清单

三端 MUST 提示「请回复清单编号；多选请用逗号或空格分隔」，按同一冻结映射解析全部编号。主体和强度已确认时不重复询问。

### Scenario: 用户回复多个有效编号

- **GIVEN** 完整清单已展示
- **WHEN** 用户回复一个或多个有效编号，包含重复编号
- **THEN** 去重并保留全部有效选择，编号 0 对应内置规则包，其余对应真实清单 ID
- **AND** 直接校验并发起审查，不追加完成或开始确认

### Scenario: 回复混有无效编号或自由文本

- **GIVEN** 主体、强度和完整候选已确定
- **WHEN** 回复包含无效编号、翻页指令或自由文本
- **THEN** 保留已完成步骤和候选，重新提示编号格式并展示完整清单
- **AND** 不只采用回复中有效的部分，不进入翻页或搜索流程

### Scenario: 用户提前指定清单

- **GIVEN** 用户在进入编号选择前已明确指定清单且能在本次查询中唯一匹配
- **WHEN** Skill 收集审查输入
- **THEN** 直接复用已确认值并跳过对应步骤

## Requirement: 选择方式不改变阶段顺序

三端 MUST 按「主体 → 强度 → 清单」独立收集各业务维度。WorkBuddy 主体和强度使用正文编号列表；Codex 在当前原生选项工具可用且候选符合容量时使用单选卡；豆包沿用宿主单选能力或编号协议。清单阶段始终完整展示并等待编号回复。
