# 提案：审查清单对话分页

## 用户价值

当可用审查清单超过 WorkBuddy 单次选择组件的容量时，用户仍可浏览并选择全部真实清单，且不会把清单分页误认为“清单/立场方”两个问题之间的翻页。

## 范围

- 审查清单选择成为独立的第一交互阶段，每页展示 4 个真实清单。
- 使用稳定全局编号，支持上一页、下一页、完成选择和按名称搜索。
- 跨页保留已选清单，并在完成时统一映射为 CLI 查询得到的真实 ID。
- 清单完成后才进入独立的立场方选择阶段，禁止合并到同一选择卡片。

## 验收标准

- CLI 读取全部清单分页，候选集合不因宿主选项上限截断。
- 每页最多展示 4 个真实清单，并显示 `第 X/Y 页，已选择 N 项`。
- 用户翻页、回退或按完整名称输入时均基于同一完整候选集合。
- 清单选择完成前不展示立场方选择；完成后使用新的独立交互展示立场方。

## 非目标

- 不修改 `checklist list` 接口、分页参数或响应结构。
- 不修改 WorkBuddy 原生选择组件。
- 不改变主体提取、任务发起或规则 ID 的服务端语义。
