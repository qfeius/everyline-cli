# 当前 CLI 的交互式清单与规则管理

只有用户明确要求管理清单或规则时使用本流程。所有命令和参数以实时 `--help` 为准，默认使用 JSON 输出并读取全部分页。先按主 Skill 固定 `<profile>` 与 `<identity>`，本流程的每条授权、查询和写入命令都显式携带 `--profile <profile> --as <identity>`。

## 共同规则

- 写操作前先查询并唯一定位目标，内置清单只允许查询和选择。
- 新增和更新先展示名称及实际字段摘要，取得用户确认后执行。
- 只修改用户明确提出的字段；当前更新命令要求完整对象时，先读取当前值并合并未修改字段。
- 清单和规则的批量创建、批量更新均支持真实写入，必须使用一次批量请求，不拆成多次单项请求。
- 删除确认必须针对具体目标，确认前不传 `--yes`。

## 自定义清单

### 新增或重新配置

1. 查询全部规则分组和分组下规则，读取所有分页。
2. 向用户展示规则名称、分组和风险等级，内部保存真实规则 ID。
3. 收集清单名称和最终规则集合，展示摘要并确认。
4. 新增使用 `checklist create`；更新先读取当前集合并展示新增、移除差异，再使用 `checklist update`。
5. 批量创建或批量更新时，展示全部清单摘要或差异并取得一次明确确认，然后调用一次对应批量命令。

### 删除

1. 精确定位自定义清单并展示名称、规则名称和已知影响。
2. 用户明确确认后调用 `checklist delete --profile <profile> --as <identity> --id <id> --yes --output json`。
3. 用户取消、目标变化或定位不唯一时停止。

## 审查规则

### 新增或编辑

1. 新增规则先让用户从真实规则分组中选择。
2. 收集名称、风险等级、审查逻辑和可选风险说明，并按实时 Schema/帮助校验。
3. 编辑时只改变用户指定字段，但向 CLI 提交其当前接口要求的完整对象。
4. 展示完整摘要或字段差异，确认后执行 `rule create` 或 `rule update`。
5. 同一分组内批量新增时，展示全部规则摘要并取得一次明确确认，然后调用一次 `rule batch-create`；不拆成多次 `rule create`。
6. 同一分组内批量更新时，展示全部规则差异并取得一次明确确认，然后调用一次 `rule batch-update`。

### 删除

1. 精确定位规则，展示规则名称、所属分组和删除影响。
2. 用户明确确认后调用 `rule delete --profile <profile> --as <identity> --group-id <group-id> --rule-id <rule-id> --yes --output json`。
3. 不在删除前扫描或修改清单的 `reviewRuleIds`，规则引用关系由服务端删除接口处理。
4. 用户取消、目标变化或定位不唯一时停止。

规则分组删除会按现有服务端语义级联删除所属规则。执行前必须查询并展示分组内全部规则，取得针对整个影响集合的明确确认，然后才调用 `rule group delete --yes`。
