# 当前 CLI 的交互式清单与规则管理

只有用户明确要求管理清单或规则时使用本流程。所有命令和参数以实时 `--help` 为准，默认使用 JSON 输出并读取全部分页。

## 共同规则

- 写操作前先查询并唯一定位目标，内置清单只允许查询和选择。
- 新增和更新先展示名称及实际字段摘要，取得用户确认后执行。
- 只修改用户明确提出的字段；当前更新命令要求完整对象时，先读取当前值并合并未修改字段。
- 批量创建和批量更新在当前 CLI 中仅支持 dry-run，不把 dry-run 描述为写入成功。
- 删除确认必须针对具体目标，确认前不传 `--yes`。

## 自定义清单

### 新增或重新配置

1. 查询全部规则分组和分组下规则，读取所有分页。
2. 向用户展示规则名称、分组和风险等级，内部保存真实规则 ID。
3. 收集清单名称和最终规则集合，展示摘要并确认。
4. 新增使用 `checklist create`；更新先读取当前集合并展示新增、移除差异，再使用 `checklist update`。

### 删除

1. 精确定位自定义清单并展示名称、规则名称和已知影响。
2. 用户明确确认后调用 `checklist delete --id <id> --yes --output json`。
3. 用户取消、目标变化或定位不唯一时停止。

## 审查规则

### 新增或编辑

1. 新增规则先让用户从真实规则分组中选择。
2. 收集名称、风险等级、审查逻辑和可选风险说明，并按实时 Schema/帮助校验。
3. 编辑时只改变用户指定字段，但向 CLI 提交其当前接口要求的完整对象。
4. 展示完整摘要或字段差异，确认后执行 `rule create` 或 `rule update`。

### 删除

当前 CLI 没有引用感知的原子级联删除接口，因此只安全支持未被清单引用的规则：

1. 读取全部自定义清单分页，检查每个清单的 `reviewRuleIds`。
2. 未发现引用时，展示规则名称、所属分组和影响；用户确认后调用 `rule delete --yes`。
3. 发现任何引用时，列出全部受影响清单并停止，不调用清单更新或规则删除。
4. 不把解除清单引用和删除规则拆成多个 CLI 请求。

规则分组删除会按现有服务端语义级联删除所属规则。执行前必须查询并展示分组内全部规则，取得针对整个影响集合的明确确认，然后才调用 `rule group delete --yes`。
