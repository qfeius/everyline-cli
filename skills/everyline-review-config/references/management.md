# 当前 CLI 的清单、规则与分组管理流程

## 共同协议

固定 `<profile>` 与 `<identity>`，每条命令显式携带 `--profile <profile> --as <identity>`，默认使用 `--output json` 并读取全部分页。

读取与定位：

1. 用本次身份的实时查询取得真实 ID、类型、归属和关联，不复用其他身份、旧会话或截图中的 ID。
2. 名称不唯一时展示名称、ID、类型或分组等真实可区分信息。
3. 当前状态、类型或关联集合不完整时停止写入，不猜测。

写入与验证：

1. 先读取最新状态和影响，展示准确差异并取得一次具体确认。
2. 确认后复查；任何漂移都重新计算、展示并确认。
3. 实时帮助支持 `--dry-run` 或等价预检时，使用与正式写入相同的请求。
4. 只调用一次原子写命令；写入后回读对象及关联。
5. 临时请求文件权限受限，完成后清理；用户内容不拼进 shell 命令。

## 可用命令面

实际参数和请求字段以实时帮助为准：

```text
checklist list
checklist create --input <request-file>
checklist update --id <checklist-id> --input <request-file>
checklist delete --id <checklist-id> --yes

rule group list
rule group create --input <request-file>
rule group update --id <group-id> --input <request-file>
rule group delete --id <group-id> --yes

rule list --group-id <group-id>
rule create --group-id <group-id> --input <request-file>
rule update --group-id <group-id> --rule-id <rule-id> --input <request-file>
rule delete --group-id <group-id> --rule-id <rule-id> --yes
```

命令存在只表示入口已注册；引用枚举、完整最终状态和服务端原子语义仍需通过帮助与结构化结果确认。

## 审查清单

### 查询

读取全部分页。展示名称、真实 ID、内置/自定义类型，以及当前包含规则的名称和真实 ID。类型或规则集合不完整时不进入写入。

### 创建自定义清单

1. 收集名称，完整查询全部规则分组和规则。
2. 让用户选择最终规则集合；重名规则同时展示分组和 ID。
3. 展示新建名称和最终集合，确认后调用一次 `checklist create`。
4. 回读新对象，核对名称、类型和完整规则集合。

不把未查询到的规则名称转换为猜测 ID，也不创建内置清单。

### 重命名或重新配置

1. 唯一定位自定义清单，读取当前名称与完整规则集合。
2. 展示旧名称与新名称，或完整计算保留、新增和移除规则；无变化时不写入。
3. 确认且复查无漂移后，使用一次 `checklist update` 提交最终状态。
4. 回读并逐项核对。

未取得当前完整集合时，不把“增加一条规则”实现为覆盖未知集合。

### 删除

1. 确认目标类型为自定义，展示名称、ID、全部规则及 CLI 返回的影响。
2. 用户确认后复查；目标或影响变化时重新确认。
3. 帮助确认显式删除入口后调用一次 `checklist delete --yes`。
4. 回读并按 ID 确认目标已不存在；同名不同 ID 不表示已删除。

## 审查规则

### 查询

先读取全部规则分组，再读取相关分组下全部规则分页。展示名称、真实 ID、所属分组、风险等级和用户需要的内容；判断引用前取得完整清单引用集合。

### 创建

1. 从真实分组中选择目标分组。
2. 收集并校验：名称必填；风险等级为「红线 / 高 / 中 / 低」之一；审查逻辑必填且不超过 3000 字；风险说明选填且不超过 1500 字。
3. 展示分组、名称、风险等级、逻辑和说明摘要，确认且复查后调用一次 `rule create`。
4. 回读真实 ID、内容和所属分组。

### 编辑

1. 通过分组与规则唯一定位，读取完整内容和清单引用。
2. 只修改用户明确指定的字段；按创建规则约束校验最终对象。
3. 展示逐字段差异；无变化时不写入。
4. 确认且复查后调用一次 `rule update`，再回读全部字段和引用。

### 调整所属分组

1. 唯一定位规则、当前分组和用户选择的真实目标分组。
2. 展示「当前分组 → 目标分组」、规则 ID 和全部清单引用。
3. 只有实时帮助提供单次原子调整归属时才确认并执行；不以复制规则、更新清单、删除旧规则的多步方式模拟。
4. 确认后复查规则、两个分组和引用；执行后回读归属与引用。

### 删除

1. 读取规则完整内容、所属分组和全部清单引用。
2. 展示名称、ID、分组、受影响清单及每条将解除的关联，取得针对该级联范围的确认。
3. 复查引用；变化时重新确认。
4. 只有 CLI 提供解除全部引用并删除规则的单次原子操作时调用 `rule delete --yes`。
5. 回读规则、原分组和受影响清单，确认规则不存在且引用解除。

不先逐个更新清单再删除规则。

## 规则分组

### 查询、创建和重命名

- 查询：读取全部分组分页以及每个相关分组下的全部规则。
- 创建：收集准确名称，确认后调用一次 `rule group create`，回读真实 ID 与名称。
- 重命名：唯一定位并展示「旧名称 → 新名称」，确认、复查后调用一次 `rule group update`，再回读验证。

名称重复时展示真实 ID，不替用户合并分组。

### 删除

1. 唯一定位分组，读取其全部规则以及每条规则的全部清单引用。
2. 汇总并展示分组名称与 ID、全部规则和将解除的清单引用。
3. 用户确认后重新读取全部对象；任何变化都重新展示并确认。
4. 只有 CLI 提供覆盖该范围的单次原子级联删除时调用 `rule group delete --yes`。
5. 回读分组、规则和受影响清单，确认删除与解绑均完成。

影响范围不完整或缺少原子级联能力时不产生写入。

## 结果表达

- 查询成功：只展示用户需要的名称、类型、ID、归属和关联。
- 写入成功：展示实际变化、真实对象 ID 和回读后的最终状态。
- 写入结果未知：说明最后确认状态和真实错误，先回读再决定下一步。
- 授权或权限失败：保持当前身份，转 `everyline-review` 的公共接入流程 恢复。
- 服务端拒绝：保留真实原因和 request ID，不包装为成功。
