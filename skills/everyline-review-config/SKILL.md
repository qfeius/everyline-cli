# everyline-review-config

使用 `everyline-cli` 管理审查清单、审查规则和规则分组。执行本 Skill 前通过宿主技能加载能力读取 `everyline-review` 中的「执行前检查」「安装与更新」「Profile 与身份」和「通用边界」，遵守其安装、身份、授权、结构化输出和安全约定；出现鉴权问题时进入其「状态、退出与恢复」。配置管理始终由本 Skill 负责，复用公共接入后返回中断步骤，不进入合同上传或审查流程。不要假定跨 Skill 相对路径可用；依赖未安装时先安装或导入 `everyline-review`，豆包云端分别导入两个 ZIP。

## 触发边界

本 Skill 固定使用 `blue` 环境，遵守 `everyline-review` 的环境校验规则。显式指定其他环境或实际连接地址不属于 blue 的 Profile 时，报告环境不匹配并停止，不执行清单、规则或分组的查询与写入。恢复配置任务时也先核对 blue Profile，再复用原身份和会话。

在用户明确要求以下任一事项时使用：

- 查询、创建、重命名、重新配置或删除审查清单；
- 查询、创建、编辑、调整所属分组或删除审查规则；
- 查询、创建、重命名或删除规则分组；
- 查看规则归属、清单引用或删除影响。

以下事项不使用本 Skill：

- 在一次合同审查中选择已有清单；该步骤属于 `everyline-review`；
- 发起、继续或查询合同审查任务；
- 合同起草、一般法律咨询或其他合同 CLI 操作。

不要因为用户浏览过某个对象就推断其同意修改。查询不授权写入，一次确认也不能沿用到另一个对象或另一种操作。

“新建或修改清单后审查合同”先按本 Skill 完成具体写入确认、写入与回读，再携带真实清单 ID 和已确认业务输入转回 `everyline-review`；发起审查的请求本身不代表用户确认配置写入。

## 运行时就绪检查

每次会话首次进入本 Skill 时执行：

```bash
command -v everyline-cli
everyline-cli version --output json
everyline-cli checklist --help
everyline-cli rule --help
everyline-cli rule group --help
```

先复用 `everyline-review` 的首次使用提示、Profile、身份与授权门禁检查；将本 Skill 实际加载的 `metadata.version` 用于版本提示，同一会话不重复提示。固定 `<profile>` 与 `<identity>`，授权与业务命令显式携带 `--profile <profile> --as <identity>`。每条 user 命令复用同一 Device 会话：豆包普通工作任务（含本地电脑）注入同一 `SESSION_ID` 并使用同一初始工作目录，WorkBuddy 注入同一 `CODEBUDDY_SESSION_ID`，AgentKit 保留平台工作区与注入密钥。

记录 `version` 返回的 `updateRequired`，独立配置任务在查询或单次已确认写入及回读完成后更新；组合任务还需等后续审查取得终态、结果已获取且整条业务流程结束，避免两个阶段之间替换 CLI。

在每次写入前，再读取将要执行的具体子命令 `--help` 和 CLI 提供的请求结构说明。只使用实时帮助中已注册的命令、参数和请求字段，不凭本文猜测请求体。

当前操作只有同时满足以下条件才就绪：

1. 查询结果能返回真实对象 ID、类型、归属和关联关系，并可读取全部分页；
2. 清单结果能可靠区分内置与自定义，并返回重新配置所需的完整规则集合；
3. 更新命令能表达用户要求的完整最终状态；
4. 删除规则或分组时，CLI 能完整返回引用与级联影响，并提供服务端原子删除能力；
5. 调整规则分组时，CLI 提供单次原子变更能力；
6. 命令能输出可解析的结构化结果。

任一必要能力缺失时，明确说明“当前 CLI 版本未支持本次配置操作”，列出缺失能力并停止写入。可以继续无风险的只读查询；不得改用未注册接口、通用网络命令、自行构造网络请求或多次写入来模拟目标能力。

本 Skill 只使用以下单项命令面；实际参数和请求体仍以当前版本帮助为准：

```text
checklist list
checklist create --input <request-file>
checklist update --id <checklist-id> --input <request-file>
checklist delete --id <checklist-id> --yes

rule group list
rule group create --input <request-file>
rule group update --id <group-id> --input <request-file>
rule group delete --id <group-id> --yes

rule list --group-id <group-id>
rule create --group-id <group-id> --input <request-file>
rule update --group-id <group-id> --rule-id <rule-id> --input <request-file>
rule delete --group-id <group-id> --rule-id <rule-id> --yes
```

上述删除命令的存在不代表级联条件已经满足；仍须通过实时帮助和结构化结果确认引用枚举与原子语义后才能调用。

## 通用执行协议

### 读取与定位

1. 使用 `--output json` 获取结构化结果。
2. 查询存在分页时持续读取，直到服务端明确表示没有下一页；不能把第一页当作完整集合。
3. 用本次查询得到的真实 ID 操作，不复用其他身份、历史会话或旧截图中的 ID。
4. 名称不唯一时，展示名称、ID、类型或所属分组等真实可区分信息，让用户选择。
5. 不能唯一定位、不能确认类型或不能取得完整关联时停止，不猜测。

### 写入门槛

创建、更新、调整归属和删除均按以下顺序执行：

1. 读取目标对象最新状态和所有受影响关系。
2. 向用户展示准确对象以及将发生的变化；更新使用“修改前 → 修改后”，集合变化分别列出“新增”和“移除”。
3. 明确询问是否执行这一次具体写入，并等待用户确认。用户未确认、确认含糊或改变目标时不执行。
4. 确认后立即重新查询目标及关联。状态变化时重新计算差异和影响，再次展示并取得新确认。
5. 若实时帮助支持预检，先用相同请求执行预检；预检成功不等于写入成功。
6. 只调用一次与用户确认内容一致的单项写命令。删除时仅在前述门槛均满足后传入 CLI 要求的显式确认参数。
7. 写入返回后重新查询目标及关联，验证真实最终状态；不要只根据退出码、进度文本或预检结果宣布成功。

请求体优先通过权限受限的临时 JSON 文件和 `--input` 传递。不要把用户内容拼进 shell 命令，不调用任何批量命令。操作结束后仅清理本流程创建的临时文件。

### 结果表达

- 查询成功：展示用户需要的对象名称、类型、ID、归属和关联，不输出无关响应体。
- 写入成功：展示实际变更、真实对象 ID 和回读后的最终状态。
- 写入结果未知：说明最后已确认的状态和真实错误，不盲目重试；先回读再决定是否继续。
- 权限或授权失败：保持当前身份，进入 `everyline-review` 的授权恢复流程；不得自动换成另一身份。
- 服务端拒绝：返回真实原因和 CLI 实际提供的请求标识，不包装成成功。

## 审查清单

### 查询清单

使用已注册的 `checklist list`，读取全部分页。每个清单至少展示：

- 名称和真实 ID；
- 内置或自定义类型；
- 当前包含的规则名称及真实 ID。

结构化结果无法区分类型或只返回部分规则时，不执行后续写入。内置清单仅可查询或由审查流程选择，禁止重命名、重新配置或删除，即使底层命令没有主动拦截也不得尝试。

### 创建自定义清单

1. 收集清单名称。
2. 完整查询全部规则分组及其规则。
3. 让用户选择最终包含的规则；名称重复时同时展示分组和 ID。
4. 展示“新建自定义清单”的名称以及最终规则集合并取得确认。
5. 使用实时请求结构生成输入文件，调用已注册的 `checklist create --input ...`。
6. 回读新清单，核对名称、类型和完整规则集合。

不得把未查询到的规则名称转成猜测 ID，也不得创建内置清单。

### 重命名或重新配置自定义清单

1. 唯一定位自定义清单并读取当前名称、完整规则集合。
2. 重命名时展示旧名称与新名称。
3. 重新配置时完整查询可用规则，让用户给出最终规则集合。
4. 计算并展示保留、新增和移除的规则；没有变化时不调用更新。
5. 用户确认且复查无漂移后，使用 `checklist update --id ... --input ...` 一次提交最终状态。
6. 回读并逐项核对名称和规则集合。

不要把“增加一条规则”实现为覆盖未知的部分集合；未取得当前完整集合时停止。

### 删除自定义清单

1. 唯一定位目标，确认结构化类型为自定义。
2. 展示清单名称、ID、包含的全部规则及 CLI 返回的其他影响。
3. 明确询问是否删除这个清单。
4. 用户确认后重新读取；目标或影响变化时重新确认。
5. 只有实时帮助确认删除命令与显式确认参数可用时，执行单项 `checklist delete`。
6. 回读并确认目标已经不存在；同名但不同 ID 的清单不得视为已删除。

## 审查规则

### 查询规则

先完整查询规则分组，再对每个相关分组读取全部规则分页。展示规则名称、真实 ID、所属分组、风险等级，以及用户要求的内容。需要判断引用时，还必须取得每条规则被哪些清单引用的完整集合。

### 创建规则

1. 让用户从实际存在的规则分组中选择一个目标分组。
2. 收集并校验：
   - 规则名称：必填；
   - 风险等级：必选“红线 / 高 / 中 / 低”之一；
   - 审查逻辑：必填，最多 3000 字；
   - 风险说明：选填，最多 1500 字。
3. 展示分组、规则名称、风险等级、审查逻辑和风险说明的完整摘要。
4. 用户确认且分组仍存在后，调用已注册的 `rule create` 单项命令。
5. 回读并核对真实规则 ID、内容和所属分组。

不得新建一个近似分组来代替用户选择，也不得把非法风险等级自动改成最接近的值。

### 编辑规则

1. 通过“分组 + 规则”唯一定位并读取完整当前内容与清单引用。
2. 只修改用户明确提出的字段，未修改字段保持原值。
3. 按创建规则的约束重新校验最终内容。
4. 展示逐字段的修改前后差异；没有变化时不调用更新。
5. 用户确认且复查无漂移后，调用已注册的 `rule update` 单项命令。
6. 回读并核对所有字段和引用关系。

### 调整规则所属分组

1. 唯一定位规则、当前分组和用户选择的真实目标分组。
2. 展示“当前分组 → 目标分组”、规则 ID，以及该规则被引用的全部清单。
3. 只有实时帮助确认 CLI 支持单次原子调整归属时才取得确认并执行；不能用“复制新规则、改清单、删除旧规则”模拟。
4. 确认后重新查询规则、两个分组和引用；任一变化都需要重新确认。
5. 执行一次原子变更，随后回读规则归属与全部引用。

### 删除规则

1. 唯一定位规则，读取完整内容、所属分组和全部清单引用。
2. 展示规则名称、ID、所属分组、所有受影响清单，以及将解除的每一条关联。
3. 明确询问是否按该级联范围删除规则。
4. 用户确认后重新读取规则和全部引用；引用有任何变化时展示新影响并重新确认。
5. 只有 CLI 明确提供“解除全部引用并删除规则”的单次原子操作时，才执行带显式确认的单项删除命令。
6. 回读规则、原分组和受影响清单，确认规则不存在且引用已全部解除。

不得先逐个更新清单再删除规则。无法完整枚举引用、原子能力不可用或用户未确认时，不解除任何关联，也不删除规则。

## 规则分组

### 查询、创建和重命名

- 查询：使用 `rule group list` 读取全部分页，并读取每个分组下的全部规则。
- 创建：收集分组名称，展示准确名称，取得确认后调用 `rule group create`；回读真实 ID 和名称。
- 重命名：唯一定位分组，展示“旧名称 → 新名称”，取得确认并复查后调用 `rule group update`；回读验证。

名称重复时展示真实 ID 让用户选择，不替用户合并分组。

### 删除规则分组

删除分组会影响其规则以及引用这些规则的清单，按高风险级联操作处理：

1. 唯一定位分组，读取分组下全部规则。
2. 对每条规则读取全部清单引用，汇总分组、规则和受影响清单的完整级联范围。
3. 向用户展示分组名称与 ID、将删除的全部规则、将解除的全部清单引用，并明确询问是否执行。
4. 用户确认后重新读取全部对象；分组、规则或引用变化时展示新范围并重新确认。
5. 只有 CLI 明确提供覆盖上述范围的单次原子级联删除时，才执行带显式确认的 `rule group delete` 单项命令。
6. 回读分组、规则和受影响清单，确认删除与解绑均已完成。

不得拆成逐条删规则、逐个改清单和最后删分组。服务端无法保证原子性、影响范围不完整或用户未确认时，停止且不产生任何变更。

## 安全与真实性红线

- 只调用 `everyline-cli` 实时帮助中已注册的命令；禁止裸 API、内部地址和自行拼接 HTTP 请求。
- 不输出或记录任何凭据、Token、Cookie，也不把合同或规则内容发送给流程外服务。
- 不猜测对象 ID、类型、归属、引用关系、级联结果或权限。
- 不执行批量创建、批量更新或批量删除。
- 不在用户确认前写入，不把预检或退出码成功描述为业务写入成功。
- 不在未知结果下自动重试可能重复的写入；先回读真实状态。
- 不虚构成功、对象 ID、影响范围或回读结果。
